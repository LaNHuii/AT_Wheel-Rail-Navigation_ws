# 阶段 4.4.1 验收记录：Gazebo 水泥平面

日期：2026-09-20

## 范围

本阶段只验证 Gazebo Classic 中的水泥平面、四舵轮接触物理和基本全向运动。不包含圆轨、上轨、传感器、定位或 Nav2。

## 实现

- 使用 ODE，物理步长 1 ms，控制器更新频率 100 Hz。
- 详细 STL 仅用于显示；物理接触使用简化惯性和碰撞体，避免高面数网格导致接触不稳定。
- `gazebo_ros2_control/GazeboSystem` 替换阶段 4.3 的模拟硬件，导航侧仍使用相同的 `cmd_vel` 和 `SwerveState` 接口。
- 加入 Gazebo 专用命令符号适配器。模块顺序为 FL、FR、RR、RL，驱动符号为 `[-1, +1, -1, -1]`，对应 CAD 导出后各轮轴在基座坐标系中的实际方向。
- 符号与零点被限制在硬件适配层，后续可针对 Gazebo 和实车分别替换，不进入导航算法。
- Gazebo 状态统一发布在 `/gazebo/model_states` 和 `/gazebo/link_states`。

## 发现并修正的问题

1. Humble 的 `gazebo_ros2_control` 会将 `robot_description` 转交给 ROS 参数解析器，XML 注释中的冒号会触发解析失败。启动时只对生成后的参数值移除 XML 注释，源码注释保留。
2. 初始世界未加载状态发布插件，自动验收无法获取模型位姿；已加入 `libgazebo_ros_state.so`。
3. 四轮统一正轮速不能表示统一前进方向；已按关节轴方向加入 Gazebo 专用符号适配。
4. Python 适配器首次在 Ctrl-C 时重复关闭 ROS 上下文；已修正并验证所有节点干净退出。

## 自动验收结果

运行 `ros2 run wr_gazebo verify_flat_ground.py`：

- 静止：通过；模型根高度约 -0.0001 m，横滚/俯仰接近 0，无穿透爆炸或明显漂移。
- 前进：3 s、指令 0.15 m/s，X 位移 0.443 m。
- 横移：3 s、指令 0.15 m/s，Y 位移 0.445 m。
- 原地旋转：4 s、指令 0.25 rad/s，航向变化 0.961 rad。
- 停止：1 s 平面漂移 0.001 m。
- 启动与 Ctrl-C 关闭：Gazebo、状态发布、舵轮控制和命令适配节点均干净退出。

## 仍未确认的内容

- 当前质量、惯量、轮胎尺寸和接触参数是仿真暂定值，不能直接作为实车参数。
- 水泥平面通过不代表圆轨接触通过；内侧轨道圆柱的几何和接触属于 4.4.2/4.4.3。
- 当前测试验证了运动方向和稳定性，尚未把速度跟踪误差作为性能指标。

结论：阶段 4.4.1 通过，允许进入 4.4.2。
