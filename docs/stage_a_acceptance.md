# 阶段 A 验收记录：上下位机控制边界

日期：2026-09-21

## 目标

在继续圆轨仿真前，明确上位机、Gazebo和STM32下位机的职责，避免实车上由工控机和STM32重复计算四舵轮运动学。

## 电控仓库只读结论

STM32工程已经包含 `vx、vy、wz` 到四个轮速和四个舵角的逆运动学、等效舵角选择、限速、斜坡、电机控制和故障停车。

现有物理链路为：

- FDCAN1 500 kbit/s：4台驱动电机；
- FDCAN2 1 Mbit/s：4台RS06转向电机；
- UART5：FS-iA10B遥控器；
- USART1：日志输出。

当前没有工控机命令入口，也没有工控机串口、CAN或以太网协议。

## 已实现边界

```text
/cmd_vel
   -> cmd_vel_guard（有限值、同比例限速、200 ms超时）
   -> /cmd_vel_chassis（vx、vy、wz）
      -> Gazebo：wr_swerve_controller -> 8个仿真关节
      -> 实车：通信适配器 -> STM32 -> STM32舵轮运动学
```

`wr_swerve_controller`已明确为Gazebo/算法测试后端，不进入实车启动配置。

实车通信目前只有 `dry_run` 框架。它接收和预览底盘速度，但不会发送串口字节、CAN帧或网络报文。未确定协议前不伪造实车已对接状态。

## 单元测试

速度网关新增检查：

- 限制范围内命令原样通过；
- 超限的组合速度按同一比例缩放，不改变运动方向；
- NaN/Inf命令被拒绝并清零；
- 非法限制参数拒绝启动。

与已有描述和舵轮测试合计：13项测试，0错误、0失败。

## 实车 dry-run 验收

- 运行节点只有 `/cmd_vel_guard` 和 `/real_chassis_adapter`；
- 未出现 `swerve_controller`、`controller_manager`或八关节控制话题；
- 输入 `(vx, vy, wz) = (0.20, -0.10, 0.30)`，适配器预览保持相同三轴速度；
- 停止输入超过200 ms后，预览输出为全零，`timed_out=true`；
- 两个节点均干净退出。

## Gazebo回归验收

Gazebo改为只订阅 `/cmd_vel_chassis`，上游测试脚本仍向稳定入口 `/cmd_vel`发送命令。

- 静止：通过；
- 前进位移：0.441 m；
- 横移位移：0.442 m；
- 航向变化：0.956 rad；
- 停止漂移：0.001 m；
- 所有节点干净退出。

## 尚未冻结的实车事项

- 工控机—STM32采用以太网、新串口还是CAN；
- 命令和反馈帧格式；
- 通信频率、序号、CRC、心跳和超时；
- 遥控与自主命令的优先级由上位机还是STM32最终仲裁；
- STM32如何暴露舵角、轮速、转矩、故障和模式反馈。

这些事项只影响实车传输插件和STM32新增入口，不改变导航侧的 `/cmd_vel_chassis` 逻辑接口。

结论：阶段A通过，允许进入阶段B的600 mm双圆轨仿真。
