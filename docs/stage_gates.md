# 分阶段构建与验收

本项目采用“阶段门”流程：一个阶段的实现、构建和验收全部通过后，才开始下一阶段。失败时停留在当前阶段修正，避免多个模块同时引入变量。

## 通用命令

工作空间位于含中文字符的路径中。ROS 2 Humble 的 `rosidl` 在这种路径下生成接口时可能解析失败，因此源码保留原位，构建、安装和日志统一放在 ASCII 路径 `/tmp/at_wheel_rail_navigation`。

```bash
./tools/stage_build.sh
./tools/stage_test.sh
source /tmp/at_wheel_rail_navigation/install/setup.bash
```

可通过 `WR_NAV_ARTIFACT_ROOT` 指定其他仅含 ASCII 字符的产物目录。

## 阶段门

| 阶段 | 目标 | 进入下一阶段的最低条件 |
|---|---|---|
| 4.1 | 工作空间、稳定消息与服务接口 | 全量编译成功；接口可被 `ros2 interface show` 发现 |
| 4.2 | 导入并修正机器人描述 | Xacro/URDF 解析通过；TF 树、关节、惯量和网格检查通过 |
| 4.3 | 四舵轮与 `ros2_control` | 8 个关节可控；限位、零点、超时停车和状态反馈通过 |
| 4.4 | 地面、圆轨与接触模型 | 自由路面和轨道上均无异常穿透/爆炸；驶入驶出可重复 |
| 4.5 | MID-360、IMU 与真值基线 | 话题频率、时间戳、坐标系、噪声和遮挡检查通过 |
| 4.6 | 定位、Nav2、轨内控制和任务编排 | 各模块先独测，再执行完整覆盖任务回归 |

每个阶段的验收记录应包含：代码版本、执行命令、通过项、失败项、尚未标定参数和是否允许进入下一阶段。

当前状态：4.4 的 Gazebo 基线已于 2026-09-22 通过，详见
`stage_b_physical_model_clamp_transition_acceptance.md`。下一阶段为 4.5；
真实转矩阈值和真实入口误差容限仍需在上车前标定，不因仿真通过而冻结。
